## Issues Identified

1. **Arrow-key navigation from the slide trigger loses focus and stops working** (`galleryCarousel.tsx:37-53`, `:83`). When focus is on the current slide's trigger and the user presses ArrowLeft or ArrowRight, `goTo` makes that slide `hidden`. The browser moves focus to `<body>`, so further arrow presses fall outside the section's `onKeyDown` and do nothing, and assistive-technology users lose their position. The trigger is the first tab stop, so this is the main keyboard path. It breaks AC13 in normal use and contradicts the design ("focus stays on the element that had it"). Fix: in the keyboard handler (or `goTo`), when `document.activeElement` is a slide trigger, move focus to `triggerRefs.current[target]` after the index commits (for example with a flag consumed in an effect, as `refocusTrigger` already does). Add a regression test that asserts the new trigger has focus after an arrow press.  
   Severity: High  
   Blocks approval: Yes

2. **`npm run lint` does not lint any component file** (`package.json` `"lint": "eslint ./src/**/*.tsx ./src/**/*.ts"`). Under `/bin/sh` the unquoted `**` behaves like `*` and matches only 9 files, none in `src/components/`. The gallery code has never been checked by the project's lint command, so AC32's lint evidence does not cover this task.  
   Severity: Medium  
   Blocks approval: No. The script is pre-existing (not caused by this task) and the lint command does not fail. Recorded so the human knows lint evidence is hollow. See the follow-up.

3. **`primary` colour utilities are dead** (`galleryCarousel.tsx:93,138,144`, `galleryIconButton.tsx:27`). Tailwind v4 is configured with only `@import "tailwindcss"` and no `@theme`, so `bg-primary`, `border-primary`, and `outline-primary` generate no CSS. The current indicator is still distinguishable by its width, and focus outlines fall back to `currentColor`, but the design's primary accent never appears.  
   Severity: Medium  
   Blocks approval: No. AC11 and AC13 visibility are still met by shape and the `currentColor` outline. This is a design deviation. A project-level primary token is a design-system question.

4. **Duplicate heading id with two galleries on a page** (`ImageGallery.tsx:7`, carry-forward 2). `HEADING_ID` is a constant, so two galleries produce duplicate ids and the second carousel's `aria-labelledby` resolves to the first gallery's heading.  
   Severity: Medium  
   Blocks approval: No. A single gallery per page, the specified case, works correctly. Multiple instances are outside the spec's stated scenarios, though the fix is cheap (derive the id from the rendering uid or the data source id).

5. **Items with an empty or unpublished Image become blank slides** (`ImageGallery.tsx:15`, carry-forward 4). The filter checks only `item.fields`. `NextImage` returns null for an empty field, leaving an empty clickable trigger, an indicator, and an empty lightbox.  
   Severity: Medium  
   Blocks approval: No. This needs an author error or unpublished media, so it is outside normal use. Filter on `fields.Image?.value?.src` in normal mode, and keep the item in editing mode so the author can fix it.

6. **Backdrop-close triggers on non-backdrop gestures** (`galleryLightbox.tsx:88-94`, `:141`, carry-forward 5). A click in the gap between the lightbox prev/next buttons closes the dialog, and so does a drag-select from the caption that ends on the backdrop.  
   Severity: Low  
   Blocks approval: No. These are edge gestures; clicks on the controls, image, and caption themselves behave as AC21 requires.

7. **Lightbox image relies on field dimensions** (`galleryLightbox.tsx:121-125`, carry-forward 3). With no `fill` and no explicit width or height, `next/image` throws if the field value lacks dimensions. Confirmed from the SDK `NextImage` source, which spreads the field's width and height and removes them only when `fill` is set.  
   Severity: Medium  
   Blocks approval: No. Media Library raster images, the in-scope source, carry width and height in the field value. SVG and dimensionless sources are outside normal use. A guard or fallback (for example `fill` inside a sized box when dimensions are missing) would remove the crash path.

8. **Lightbox control placement and frame hover differ from the design.** On tablet and desktop the design puts prev/next at the vertically centred viewport edges; the implementation uses a bottom row at all breakpoints. The hover tonal shift on the slide frame is missing. `max-h-[70vh]` is an arbitrary value.  
   Severity: Low  
   Blocks approval: No. These are small design deviations that do not break an acceptance criterion.

9. **Background is not made inert while the lightbox is open** (`galleryLightbox.tsx`). Containment relies on `aria-modal` and the Tab trap. Some screen-reader and browser combinations still let the virtual cursor reach page content.  
   Severity: Low  
   Blocks approval: No. AC19's focus containment is met; virtual-cursor behaviour needs the manual screen-reader pass.

10. **Captions render as raw strings in normal mode** (`galleryCarousel.tsx:117`, `galleryLightbox.tsx:128`, carry-forward 7). The head app's `AGENTS.md` says to use SDK field components.  
    Severity: Low  
    Blocks approval: No. Normal mode has no editing chrome, so the output is equivalent. The editing path, where it matters, uses `Text`. The raw strings also serve the reserved-height grid and the accessible-name chain.

11. **Index not clamped when `items` shrinks** (`galleryCarousel.tsx:23`, carry-forward 6). If the item list gets shorter while mounted, all slides hide, the counter reads past the end, and an open lightbox returns null but keeps the scroll lock.  
    Severity: Low  
    Blocks approval: No. This only happens if content changes while the page is mounted, which is outside normal use.

12. **Duplicated SDK mock and fixtures across three test files** (carry-forward 8).  
    Severity: Low  
    Blocks approval: No. It is a cleanup. The run report gives the reason: Jest treats every `__tests__/` file as a suite, and a helper under `src/components/` would be picked up by the component-map scan. A shared helper needs a location outside both, for example a test-utils folder plus a Jest `testPathIgnorePatterns` entry.
