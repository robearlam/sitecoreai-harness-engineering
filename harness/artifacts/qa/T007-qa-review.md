## Design Alignment Review

**Matches well**

- Structure: a full-width band, a centred content container reusing `max-w-7xl` with 16, 24 and 32px padding, and a centred stack in the order heading, body, actions. In editing mode there is a labelled "Background image" slot below the action group.
- Palette and buttons: exactly the binding table and button rules. The radius, padding and weight (`rounded px-6 py-3 font-medium`) reuse the Hero Banner CTA shape without sharing code. The touch target is at least 44px (`min-h-11`). The secondary outline is 2px. Hover changes colour only, and the transition is short.
- Typography: the `<h2>` is `text-3xl md:text-4xl font-bold` with `max-w-3xl`. The body is `text-lg leading-relaxed max-w-2xl`, and its links are underlined and inherit the text colour.
- Spacing: `py-12 md:py-16` and `gap-6`, all on the design-system spacing scale.
- Image mode: the image covers the band (`absolute inset-0 object-cover object-center`) and does not set its height. The 60% black scrim and the image are both `aria-hidden`, and the image has empty alt.
- Accessibility: the section is labelled by its heading through a per-instance `useId` id. The focus ring is shown only for keyboard focus (`focus-visible`), with a 2px offset and colours per context.
- No decoration (shadows, gradients, icons), and no coupling to the Hero Banner.

**Partially aligned**

- The design asks for a single lookup that every element draws from. The resolver returns `hasScrim`, but the component renders the scrim from `look.mode === "image"`, so `hasScrim` has no effect (Issue 3).
- "When the body is empty … nothing is output": this holds for empty and whitespace values, but not for markup-only Rich Text (Issue 1).

**Deviations**

- None that break a criterion. The focus indicator uses `outline` rather than `ring`, which meets the design's "2px wide, 2px offset" intent.

## Issues Identified

**Correctness-pass carry-forwards (B)**

1. **B1 — markup-only Body renders an empty wrapper (`CallToActionBanner.tsx:26`).** Confirmed. `bodyText` trims the raw HTML, so `<p></p>`, `<p>&nbsp;</p>` or `<br>` count as content. In normal mode the result is an empty `max-w-2xl` div and an extra 24px gap. This goes against AC 4's intent and the design's "nothing is output … spacing closes up".  
   Severity: Medium  
   Blocks approval: No. It depends on the editor saving markup-only values for a cleared field. Empty and whitespace values, the cases the plan specified, are handled. The impact is cosmetic spacing, with no content or accessibility effect. Have the human check it in Pages: clear Body, then inspect the saved value or the layout JSON. If Pages saves `<p></p>` in normal authoring, this becomes a defect in normal use and should be fixed before Complete.

2. **B2 — a link with an href but no text renders the href as its label (`CallToActionBanner.tsx:28`).** Confirmed. The SDK `Link` renders `link.text || link.href`.  
   Severity: Low  
   Blocks approval: No. It happens only when an author leaves the link description empty, and the label is still discernible. This is standard SDK behaviour, and other components share it. The template help text already asks for a meaningful label.

3. **B3 — `hasScrim` is unused (`CallToActionBanner.tsx:23`, `ctaBannerBackground.ts`).** Confirmed. The scrim renders from `look.mode === "image"`, so the presentation record is not the only source for the scrim, as the design and plan ask.  
   Severity: Low  
   Blocks approval: No. The behaviour is correct today, because image mode and `hasScrim: true` coincide. This is redundancy and cleanup.

4. **B4 — tests go through DOM structure and compare class strings (`ctaBannerBackground.test.ts:53–61`; `CallToActionBanner.test.tsx:109, 116, 128, 132, 185`).** Partly confirmed. No test asserts a specific CSS class. The resolver test compares button strings for equality between records, which in effect checks which context a mode maps to. The component tests use `querySelector('section')` and `closest('[aria-hidden="true"]')` rather than role queries, and the plan explicitly sanctioned the `data-background` attribute.  
   Severity: Low  
   Blocks approval: No. This is minor test-style drift from AC 22, the tests are stable, and every required case is covered. The fix is to query the section by role (`getByRole('region')`) and to compare records by a context field rather than by class strings.

5. **B5 — in editing mode an empty Heading names the region "[No text in field]" (`CallToActionBanner.tsx:38`).** Confirmed from the SDK source. `DefaultEmptyFieldEditingComponentText` receives `tag="h2"` and `id`, so `aria-labelledby` resolves to the placeholder text. Two empty banners share that name, but their ids stay distinct.  
   Severity: Low  
   Blocks approval: No. It happens only in editing mode and does not affect visitors.

**Additional findings**

6. **The lint script does not reach the new files.** `"lint": "eslint ./src/**/*.tsx ./src/**/*.ts"` is expanded by npm's `sh` without globstar, so it matches only `src/*/*.ts(x)`, which is 9 files. CI runs the same script.  
   Severity: Medium  
   Blocks approval: No. It is pre-existing and was not introduced by this task. It does mean that the lint evidence for AC 23 does not cover this task's code. Recorded under Governance.

No blocking issues were found.
